What is in it

  • Post-quantum signatures everywhere. Blocks, votes and transactions are signed with ML-DSA (FIPS 204); SLH-DSA (FIPS 205) is there for long-lived keys.
  • Quantum-resistant transport. Peers connect over QUIC; the TLS 1.3 handshake uses the hybrid X25519MLKEM768 group, so a recorded session stays private even against a future quantum computer.
  • Fast finality. BFT consensus: a block is final when it is committed, no reorganisations.
  • Verifiable releases. Binaries and checksums are signed with Sigstore by the GitHub release workflow; the install script checks the signature before running anything.
  • Open verification path. Crypto, transaction types, light client and SDKs (TypeScript, Python) are Apache-2.0.
  • Honest limits. One operator and one validator today, no external audit, the chain may be reset. Read KNOWN-ISSUES.

Run a node

Linux x86_64 with glibc 2.35 or newer (Ubuntu 22.04+, Debian 12+). Install cosign so the release signature can be checked, then:

curl -fsSL https://raw.githubusercontent.com/v1p3r4llbl4ck-86/viper-pq-chain/main/scripts/join-testnet.sh | bash

The script downloads the signed release, verifies the genesis, writes a node config with fresh secret identity salts, and prints the start command. Your node joins through the public seed boot1.pqchain.agwswebconsulting.it:26656 (UDP for QUIC, TCP as fallback) and shows up in the counter above. Docker and build-from-source instructions are in the onboarding guide.

Problems joining? Open an issue. Security reports: SECURITY.md.

API

This page reads the public, read-only API of a full node. Try it: /v1/status, /v1/validators, /v1/algorithms, /v1/blocks/<height>. Rate limited; transactions go through a node you run yourself.

Viper PQ Chain is a one-person research project by Alberto Galassi. Test network: nothing on it has monetary value. Node software under BUSL-1.1 (Apache-2.0 from the change date), verification path under Apache-2.0.
